# Backend audit — 2026-10-31

This audit covers the active Python terminal and TypeScript cloud control plane. It does not certify production readiness, live funds, or an AWS deployment. The original preserved upstream code remains a separate optional workflow.

## Configuration boundaries

Financial replay now reads the complete ledger and snapshot history, independently of display pagination. A regression retains an older peak after more than 100,000 newer snapshots. The local replay remains linear in history size; production-scale volumes still need materialized accounting rollups.

Nested SQLite operations use savepoints so an accounting/configuration update participates in the enclosing trade transaction. A regression verifies both outer rollback and an independently rolled-back inner operation; audit events cannot accidentally commit outside the financial transaction.

The [configuration guide](05_CONFIGURATION.md) distinguishes operational settings from hard security invariants. Changing endpoint/default files cannot enable LIVE, bypass ownership, enable arbitrary contracts, raise hard financial limits or turn documented token addresses into verified metadata.

Fixed synthetic fixtures, standard indicator definitions and physical/unit conversion constants remain intentional. Existing SQLite selections and cloud agent revisions are not silently rewritten by changing defaults. Old agents must be reviewed and redeployed to change their providers.
