# Python backend guide

Read `models.py`, `settings.py`, `data.py`, `engine.py`, `risk.py`, `execution.py` and `portfolio.py` in that order for the main trading path. Read tests next to each behavior before changing it.

| File                                                       | Responsibility and entry points                                                                                                                                                                                               | Change it when                                                                                                             |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| [api.py](../../backend/api.py)                             | `create_app` owns lifespan, sessions, authorization, typed routes, validation and frontend serving. `save_strategy` is shared by HTTP configuration and local chat.                                                           | Adding an API operation or changing the local HTTP boundary. Keep business/risk math in domain modules.                    |
| [settings.py](../../backend/settings.py)                   | `RuntimeSettings` validates `config/runtime.json`; `get_settings` loads it once per process. `fingerprint` identifies the effective public defaults. Endpoint URLs cannot contain credentials or private IP literals.         | Adding an operational default, its type, bounds and cross-field validation.                                                |
| [models.py](../../backend/models.py)                       | Pydantic contracts for tokens, candles, articles, signals, proposals, risk, quotes, execution and requests. Decimal amounts serialize as strings.                                                                             | Changing an API/domain shape. Update TypeScript contracts and tests together.                                              |
| [data.py](../../backend/data.py)                           | `Providers.market`, `_candles`, `news`, `request`; normalization, canonical links, deduplication, source clocks and bounded caches. `fixture_*` are deterministic synthetic development inputs.                               | Integrating a verified read-only source or changing normalization/freshness behavior. Never hide an outage with fixtures.  |
| [strategies.py](../../backend/strategies.py)               | `REGISTRY`, `indicators`, `evaluate`: five built-ins, explicit entry/exit conditions and guarded indicator history. Legacy news evaluation remains for compatibility.                                                         | Implementing a strategy rule. A strategy emits a signal; it must not submit a trade.                                       |
| [strategy_registry.py](../../backend/strategy_registry.py) | `RuleStrategy` wraps existing strategy functions into structured evaluations with evidence and rejection reasons.                                                                                                             | Extending the common strategy contract while preserving existing implementations.                                          |
| [selection.py](../../backend/selection.py)                 | `SelectionConfig`, `rank_strategies`: continuous measured features, eligible signals, valid holdout evidence, costs and bounded model context.                                                                                | Changing ranking or switching policy. Keep eligibility independent of model recommendations.                               |
| [engine.py](../../backend/engine.py)                       | `Engine.run` executes the LangGraph; `_stage` supplies stage outputs; `authorize` refreshes data and reconciles workflow state; `control` and `scheduler_loop` manage local autonomous runs.                                  | Adding a workflow stage or scheduler behavior. Preserve one active run and explicit stage failures.                        |
| [research.py](../../backend/research.py)                   | `ResearchBridge` calls preserved upstream bull/bear researchers and a structured trader when explicitly configured.                                                                                                           | Adapting upstream research. Failure blocks model-dependent candidates; prompts do not grant execution authority.           |
| [risk.py](../../backend/risk.py)                           | `assess` calculates size and checks portfolio, losses, drawdown, freshness, duplication and exits. `validate_quote` checks the actual quote against the decision and policy.                                                  | Changing a financial safeguard. Add adversarial tests and keep hard caps in trusted code.                                  |
| [exchanges.py](../../backend/exchanges.py)                 | `SimulationAdapter` calculates reproducible simulated costs/fills. `HSKSwapAdapter` permits read-only chain/balance/receipt inspection and rejects submission. `AlpacaPaperAdapter` preserves the separate upstream boundary. | Adding a verified exchange integration. Do not turn a reference symbol into an on-chain token.                             |
| [execution.py](../../backend/execution.py)                 | `Execution.preview`, `validate_context`, `authorize`, `recover`, `reconcile`: configuration/source binding, exact quote authorization, atomic ledger writes and recovery.                                                     | Changing execution lifecycle or idempotency. Never retry an uncertain submission automatically.                            |
| [portfolio.py](../../backend/portfolio.py)                 | `Portfolio.view` replays average-cost accounting; `observe` retains the observed peak; `snapshot` records sampled equity.                                                                                                     | Changing cash, costs, realized/unrealized P&L, baseline or drawdown calculations.                                          |
| [storage.py](../../backend/storage.py)                     | `Store` owns the SQLite schema, explicit transaction lock, unique intent/ledger constraints, configuration versions and redacted audit records.                                                                               | Adding persistent entities or migrations. Protect financial atomicity; do not expose raw DB access through chat.           |
| [analytics.py](../../backend/analytics.py)                 | `aggregate`, `chart_indicators`, `correlations` produce descriptive chart data from compatible closed bars.                                                                                                                   | Changing chart math or supported display timeframes. Four-hour/daily charts do not silently change hourly strategy inputs. |
| [desk.py](../../backend/desk.py)                           | `sizing_preview`, `PriceAlerts`: Decimal capacity estimates and one-shot observed price crossings.                                                                                                                            | Changing trade-ticket presets or price alerts. An alert does not place a trade or imply external notification delivery.    |
| [backtesting.py](../../backend/backtesting.py)             | `backtest` uses previous closed evidence and next-open fills, fees/slippage, stops, configured capital and a frozen chronological holdout.                                                                                    | Changing evaluation assumptions. Never use a future article or candle for an earlier fill.                                 |
| [cloud_worker.py](../../backend/cloud_worker.py)           | `CloudWorker` runs the same engine under an approved AWS template, tenant/agent state scope, lease, durable checkpoint and review/authorization conditions.                                                                   | Changing cloud execution/recovery. It must not construct LLM clients or bypass the central model/risk boundary.            |

## Important records

- A **signal** is a strategy observation, not an order.
- A **proposal** adds amount, exit policy, source timestamps and configuration versions.
- A **risk decision** approves, reduces or rejects the proposal deterministically.
- An **intent** binds one proposal to a quote and authorization lifecycle.
- A **ledger row** is the durable source for a simulated fill.
- A **position** is reconstructed owned inventory; it is not inferred from an LLM response.
- A **snapshot** is a valuation at an observed time, not a synthetic performance curve.

The Python backend has one local account per database. Do not add `user_id` request parameters to imitate multi-tenancy. Use the separate Cognito/DynamoDB control plane for cloud users.
